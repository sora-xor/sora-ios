## Clean-start fixes discovered during normal verification

The iOS splash path previously persisted an empty network snapshot before any wallet existed. It now leaves a truly pristine store untouched. A current empty SQLite database with ordinary WAL/SHM files is admitted after read-only inventory and protected-key checks, without creating wallet migration backups for a nonexistent account. Missing databases with orphaned sidecars, retained PIN/selection/version evidence, corrupt pointers and installed-wallet safety checks remain protected by passing regression tests. These are admission fixes; no database schema or transaction format changed.

Android’s older encrypted-DataStore adapter was incompatible with DataStore 1.1. The compatible adapter retains the encrypted-file scheme, paths and key handling; a device test reads legacy preference bytes, updates and reopens them. Narrow dependency locks/hashes were updated. Optional catalog/holdings read failures now surface unavailable states without terminating local navigation, while cancellation and required runtime/transaction checks remain strict. Swap shows an explanation above its disabled unavailable-assets action.
